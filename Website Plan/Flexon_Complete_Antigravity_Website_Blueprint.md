### The intended experience

A visitor should understand within seconds: who Flexon is; how sport connects its work to community participation and the Global Goals; what has happened; what they can join or propose; who leads the foundation; and how to support it. The site combines premium animated 2D/3D sports artwork with genuine event documentation and clear institutional information. It should feel like a credible sports foundation, not a gym, a game loading screen or a generic technology landing page.

Primary journeys:

1. Discover foundation → explore initiative → view confirmed opportunity → enquire/register through its approved route.
2. Explore Hyderabad archive → see photographs/results if available → follow future edition updates.
3. Institution/business/club → choose collaboration need → submit scoped enquiry → receive a stored reference.
4. Donor → read purpose and verified eligibility → donate through a configured secure gateway, or send a donation enquiry while payment is unavailable.
5. Parent/guardian → football camp information → adult enquiry → human follow-up.
6. Visitor → automated chat → select need → get verified answers → optionally request contact → conversation and consent saved securely.

### Motion choreography

- First paint: heading, description, CTAs and a static responsive poster visible. No blocking progress percentage.
- 0–1.2 s: ribbon/path gently draws; objects settle 10–18 px.
- 1.2–3.5 s: runner/ball suggests movement with a small loop segment; no camera orbit or motion blur over content.
- By 5 s: hero settles and stops. Provide Pause while playing; optional Replay afterwards.
- Below fold: one-time opacity + translateY 16 px over 450 ms. Content is visible without JS; do not hide all content on failed hydration.
- Hover: card image max scale 1.025; arrow moves 3 px; equivalent keyboard focus.
- A 3D interaction, if added, rotates a decorative object at most a few degrees and never captures scrolling. No cursor replacement, sound or compulsory intro.
- Mobile, reduced motion, unsupported WebGL and data-saving conditions: static poster and simple CSS states. Respect preferences on first render, not after animation starts.
- Use ONE selected motion approach: CSS/SVG for most UI; optional one lazy-loaded 3D canvas only if necessary. Do not install overlapping animation libraries for the same effect.

Asset manifest fields: id, file, role, real-or-illustrative, creator/source, licence, approval, alt text, dimensions, desktop/mobile variants, poster, motion duration, fallback. Separate layers for ribbon/ball/runner are preferred to moving the whole flattened image. Target hero poster <=250 KB and optional motion <=2 MB where visual quality permits; performance decides inclusion. Do not ship a 20 MB scene to meet an aesthetic request.
